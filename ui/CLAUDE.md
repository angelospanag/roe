# UI — Roe Next.js app

Next.js 16 App Router SPA. A reading-focused RSS client: feed sidebar on the left, post list + inline article view on
the right.

## Stack

| Concern | Library |
|---|---|
| Build | Next.js 16 (Turbopack) + TypeScript 5 |
| UI framework | React 19 |
| Styling | Tailwind CSS v4 (`@tailwindcss/postcss` — see `postcss.config.mjs`, easy to forget) |
| Data fetching | TanStack Query v5 |
| API client | `@hey-api/client-next` + generated `client/` from `../api/openapi.yaml` |
| Icons | lucide-react |
| Package manager | **bun** — do not use npm or yarn |

## Directory structure

```
ui/
├── app/
│   ├── api/[...path]/
│   │   └── route.ts          Server-side proxy — forwards /api/* to $API_URL at request time, all HTTP methods
│   ├── layout.tsx             Root layout: Inter + Source Serif 4 via next/font, QueryClientProvider
│   ├── page.tsx               Route entry: <Home>
│   ├── providers.tsx          QueryClientProvider + hey-api client.setConfig({ baseUrl: '/api' })
│   └── globals.css            Brand tokens, warm/paper theme, prose-content article styles
├── client/                    Generated by @hey-api/openapi-ts — do not edit by hand
│   ├── types.gen.ts           TypeScript types from api/openapi.yaml
│   ├── sdk.gen.ts             Typed fetch functions (listFeeds, createFeed, listPosts, ...)
│   ├── client.gen.ts          hey-api client instance (configured in providers.tsx)
│   └── client/, core/         hey-api runtime bundle
├── components/
│   ├── Home.tsx               Top-level layout: header (logo + global unread count) + FeedSidebar + PostList
│   ├── FeedSidebar.tsx        Feed list, per-feed unread count, add/delete/refresh/mark-all-read
│   └── PostList.tsx           Post list with unread filter, pagination, inline expand-to-read
├── lib/
│   └── queries.ts             TanStack Query hooks wrapping the generated SDK (query keys, cache invalidation)
├── openapi-ts.config.ts       hey-api codegen config (input: ../api/openapi.yaml → output: client/)
├── postcss.config.mjs         Wires up @tailwindcss/postcss — required for `@import "tailwindcss"` to do anything
├── next.config.ts             standalone output (no rewrites — proxying is done via route.ts)
└── mise.toml                  Dev tooling tasks
```

## Brand tokens

Defined in `app/globals.css` `:root` (with a `prefers-color-scheme: dark` override block). Always use these — don't
hardcode hex values.

| Token | Light | Use |
|---|---|---|
| `--color-bg` | `#faf7f2` | Page background — warm paper, not clinical white |
| `--color-surface` | `#fffdfa` | Sidebar, headers, expanded post background |
| `--color-surface-hover` | `#f3ede2` | Hover state on rows/buttons |
| `--color-border` | `#e7ded0` | All borders (`* { border-color: var(--color-border) }`) |
| `--color-text` / `--color-text-muted` | `#2a2521` / `#8a7f70` | Primary / secondary text |
| `--color-accent` / `--color-accent-hover` | `#ea580c` / `#c2410c` | Classic RSS orange — links, unread markers, primary actions |
| `--color-accent-soft` | `#fdecdc` | Tinted background for selected sidebar item / unread badge |
| `--font-body` | Inter | UI chrome (sidebar, buttons, meta text) |
| `--font-serif` (`.font-serif-content`) | Source Serif 4 | Post titles and article body — editorial, reading-focused |

Unread state is a left accent bar (`border-l-2 border-l-[var(--color-accent)]`) on feed rows and post rows, not a
solid fill — mirrors the Feedly/Reeder convention of a quiet indicator rather than a loud one.

## Data layer

`lib/queries.ts` centralizes every TanStack Query hook (`useFeeds`, `useCreateFeed`, `usePosts`,
`useMarkPostRead`, ...) instead of calling the generated SDK directly from components. This exists specifically so
query-key invalidation stays consistent — e.g. `useMarkPostRead` invalidates `["posts"]`, the global unread count,
and `["feeds"]` (per-feed unread counts) in one place rather than being re-derived per call site.

All SDK calls pass `throwOnError: true` so `queryFn`/`mutationFn` can just `await` and return `.data`, letting
TanStack Query's error handling take over instead of manually branching on `{ data, error }`.

## API proxy

`app/api/[...path]/route.ts` is a Route Handler that forwards all `/api/*` requests to the Go backend, for every
HTTP method the API uses (GET/POST/PUT/PATCH/DELETE) — unlike a read-only proxy, this one forwards the request body
too. **The Go routes themselves are unprefixed** (`/feeds`, `/posts`, ...), so the proxy strips the `/api` prefix
before forwarding: `${API_URL}/${path}`, not `${API_URL}/api/${path}`.

| Context | Setting |
|---|---|
| Dev | Default: proxies to `http://localhost:8080` |
| Podman Compose | Set `API_URL=http://api:8080` in the service environment |
| Production | Set `API_URL=https://your-api-host` |

`API_URL` is a server-side env var (no `NEXT_PUBLIC_` prefix). The browser always uses relative `/api/*` paths; the
hey-api client is configured with `baseUrl: "/api"` in `providers.tsx`.

## Dev

```bash
cd ui
bun install       # first time only
bun dev           # http://localhost:3000
```

The Go API must be running on `:8080`.

## Common tasks

```bash
mise run dev        # Next.js dev server
mise run build       # production build (standalone output)
mise run typecheck   # tsc --noEmit
mise run lint        # Biome check
mise run fmt         # Biome format --write
mise run generate    # regenerate client/ from ../api/openapi.yaml
```

## Adding a new API-backed feature

1. Add/change the Huma route in `api/`, then run `mise run generate` (from repo root) to regenerate
   `api/openapi.yaml` and `ui/client/`.
2. Add a hook to `lib/queries.ts` wrapping the new generated SDK function — reuse existing query keys where the new
   call should invalidate the same cached data.
3. Consume the hook from a component; keep `client/` untouched — it's regenerated, not edited.
